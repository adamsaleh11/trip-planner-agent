## Goal

A new Next.js repo with working sign-in, a protected app shell with travel-journal visual identity, and a typed API client ready to consume the backend the moment the contract freezes.

## Responsibilities

- Scaffold: Next.js 15 App Router + TypeScript + Tailwind + shadcn/ui. Repo name `trip-journal-web`, git initialized.
- Firebase Auth: web SDK config from env; `/login` page with Google sign-in button + email/password form (sign up & sign in), error states (wrong password, existing account, weak password); auth context/provider with loading state; sign-out in the nav.
- Route protection: unauthenticated users hitting any app route redirect to `/login` (preserve intended destination); authenticated users hitting `/login` redirect to `/trips`.
- Typed API client: thin fetch wrapper that attaches a fresh ID token per request (`getIdToken()` handles refresh), reads `NEXT_PUBLIC_API_BASE_URL`, surfaces typed errors matching the contract's error shapes. Resource modules added as contract sections land.
- App shell: left nav or top bar — Trips, Map (stub route), Dashboard (stub route, Phase 4), user avatar menu. Visual identity: dark theme default, warm accent (amber/coral family), journal/atlas feel; shadcn theme tokens configured once here — every later ticket inherits.
- Page scaffolds with proper loading.tsx/empty states for /trips, /map, /dashboard.

## Tools / Interfaces

- firebase (web SDK), shadcn/ui, Tailwind. No map, no API calls beyond `/me` smoke call once backend is up.

## Patterns

- frontend-tdd: every screen ships with loading/empty/error states, responsive at 375px and 1280px, keyboard-navigable forms.
- All backend types live in one `lib/api/types.ts` generated by hand from the contract — single place to update on contract change.

## Cost rules

- None (no LLM). Firebase Auth free tier.

## Acceptance criteria

- [ ] Fresh clone + `npm i` + env file + `npm run dev` → working sign-up/sign-in/sign-out with both providers.
- [ ] Protected routing works both directions (in→login when signed out, login→trips when signed in), no flash of wrong state.
- [ ] API client attaches a valid token (verified against `GET /me` once backend is reachable) and maps 401/403/422 to typed errors.
- [ ] Shell renders the three nav destinations with polished empty states; dark theme consistent across all shadcn components.
- [ ] QA pass per frontend-tdd: mobile + desktop widths, focus states, no console errors.
